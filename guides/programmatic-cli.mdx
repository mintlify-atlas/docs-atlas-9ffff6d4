The `@wp-playground/cli` package exposes a `runCLI()` function that lets you control WordPress Playground from JavaScript or TypeScript code. Instead of launching the CLI from a terminal, you start a server programmatically, interact with it via the returned object, and shut it down when you are done. This is particularly useful for test setup, CI pipelines, and custom tooling that needs a fresh WordPress instance on demand.

## Installation

Install the package as a dev dependency in your project:

```bash
npm install --save-dev @wp-playground/cli
```

## Starting a server

Import `runCLI` and call it with `command: 'server'`. The function returns a `Promise<RunCLIServer>` that resolves once WordPress is ready to accept requests.

```typescript
import { runCLI } from '@wp-playground/cli';

const cliServer = await runCLI({
  command: 'server',
  php: '8.3',
  wp: 'latest',
  login: true,
});

console.log('WordPress is ready at:', cliServer.serverUrl);
```

Run the script using a TypeScript runtime:

```bash
npx tsx my-script.ts
```

## The `RunCLIServer` interface

`runCLI()` resolves to a `RunCLIServer` object. The fields you will use most often are:

| Property | Type | Description |
|---|---|---|
| `serverUrl` | `string` | The base URL of the running WordPress instance, e.g. `http://127.0.0.1:9400`. |
| `server` | `Server` | The underlying Node.js HTTP server. Call `server.close()` to stop it. |
| `playground` | `Pooled<PlaygroundCliWorker>` | Direct access to the PHP worker pool for advanced use cases. |
| `[Symbol.asyncDispose]()` | `() => Promise<void>` | The recommended cleanup method. Stops the server and terminates all worker threads. |

The full TypeScript interface from the source:

```typescript
export interface RunCLIServer extends AsyncDisposable {
  playground: Pooled<PlaygroundCliWorker>;
  server: Server;
  serverUrl: string;

  [Symbol.asyncDispose](): Promise<void>;
}
```

### Stopping the server

Call `[Symbol.asyncDispose]()` to perform a full cleanup — this closes the HTTP server and terminates all background worker threads:

```typescript
await cliServer[Symbol.asyncDispose]();
```

Or use the explicit `server.close()` for a lighter teardown that only stops accepting new connections:

```typescript
await cliServer.server.close();
```

<Note>
  In test frameworks that support the `using` keyword (TypeScript 5.2+ with `exactOptionalPropertyTypes`), you can let the runtime dispose automatically. For most test setups, calling `[Symbol.asyncDispose]()` in an `afterAll` or `afterEach` hook is the clearest approach.
</Note>

## Configuring with a Blueprint

Pass a Blueprint object directly to the `blueprint` property to declaratively configure the WordPress instance — install plugins, set site options, import content, and more:

```typescript
import { runCLI, RunCLIServer } from '@wp-playground/cli';

const cliServer: RunCLIServer = await runCLI({
  command: 'server',
  wp: 'latest',
  blueprint: {
    steps: [
      {
        step: 'setSiteOptions',
        options: {
          blogname: 'Blueprint Title',
          blogdescription: 'A great blog description',
        },
      },
    ],
  },
});
```

You can also pass a path to a `.json` file:

```typescript
const cliServer = await runCLI({
  command: 'server',
  blueprint: './blueprint.json',
});
```

For full type safety when building Blueprint objects, import `BlueprintDeclaration` from `@wp-playground/blueprints`:

```typescript
import type { BlueprintDeclaration } from '@wp-playground/blueprints';

const myBlueprint: BlueprintDeclaration = {
  landingPage: '/wp-admin/',
  steps: [
    {
      step: 'installTheme',
      themeData: {
        resource: 'wordpress.org/themes',
        slug: 'twentytwentyone',
      },
      options: {
        activate: true,
      },
    },
  ],
};
```

## Mounting local directories

Mount a local plugin or theme directory into the virtual filesystem using the `mount` option. `hostPath` is relative to where your script runs; `vfsPath` is the destination inside WordPress.

```typescript
import { runCLI } from '@wp-playground/cli';

const cliServer = await runCLI({
  command: 'server',
  login: true,
  'mount-before-install': [
    {
      hostPath: './my-plugin-local-path',
      vfsPath: '/wordpress/wp-content/plugins/my-plugin',
    },
  ],
});
```

Combine mounts with a Blueprint to mount and then activate your plugin:

```typescript
import { runCLI, RunCLIServer } from '@wp-playground/cli';

const cliServer: RunCLIServer = await runCLI({
  command: 'server',
  php: '8.3',
  wp: 'latest',
  login: true,
  mount: [
    {
      hostPath: './plugin/',
      vfsPath: '/wordpress/wp-content/plugins/playwright-test',
    },
  ],
  blueprint: {
    steps: [
      {
        step: 'activatePlugin',
        pluginPath: '/wordpress/wp-content/plugins/playwright-test/plugin-playwright.php',
      },
    ],
  },
});
```

## Complete example: Vitest integration tests

The following shows a full test module using Vitest. It starts a server, mounts a local plugin, runs assertions against the live WordPress site, and cleans up after each test.

```typescript
import { describe, test, expect, afterEach } from 'vitest';
import { runCLI, RunCLIServer } from '@wp-playground/cli';

describe('My Plugin Tests', () => {
  let cliServer: RunCLIServer;

  afterEach(async () => {
    if (cliServer) {
      // RunCLIServer exposes Symbol.asyncDispose as its public async cleanup API.
      await cliServer[Symbol.asyncDispose]();
    }
  });

  test('plugin activates successfully', async () => {
    cliServer = await runCLI({
      command: 'server',
      mount: [
        {
          hostPath: './my-plugin',
          vfsPath: '/wordpress/wp-content/plugins/my-plugin',
        },
      ],
      blueprint: {
        steps: [
          {
            step: 'activatePlugin',
            pluginPath: '/wordpress/wp-content/plugins/my-plugin/plugin.php',
          },
        ],
      },
    });

    const homeUrl = new URL('/', cliServer.serverUrl);
    const response = await fetch(homeUrl);

    expect(response.status).toBe(200);
    const html = await response.text();
    expect(html).toContain('My Plugin');
  });

  test('plugin works with WordPress 6.4 and PHP 8.3', async () => {
    cliServer = await runCLI({
      command: 'server',
      php: '8.3',
      wp: '6.4',
      mount: [
        {
          hostPath: './my-plugin',
          vfsPath: '/wordpress/wp-content/plugins/my-plugin',
        },
      ],
      blueprint: {
        steps: [
          {
            step: 'activatePlugin',
            pluginPath: '/wordpress/wp-content/plugins/my-plugin/plugin.php',
          },
        ],
      },
    });

    const homeUrl = new URL('/', cliServer.serverUrl);
    const response = await fetch(homeUrl);

    expect(response.status).toBe(200);
  });
});
```

## Advanced: skip WordPress and SQLite setup

When testing PHP code in isolation rather than a full WordPress site, skip the WordPress and SQLite setup for a faster boot:

```typescript
import { runCLI } from '@wp-playground/cli';

const cliServer = await runCLI({
  command: 'server',
  php: '8.3',
  wordpressInstallMode: 'do-not-attempt-installing',
  skipSqliteSetup: true,
});

await cliServer.playground.writeFile(
  '/wordpress/version.php',
  '<?php echo phpversion(); ?>'
);

const versionUrl = new URL('/version.php', cliServer.serverUrl);
const response = await fetch(versionUrl);
const version = await response.text();
console.log('PHP Version:', version); // Outputs: 8.3.x
```

## Error handling

```typescript
import { runCLI } from '@wp-playground/cli';

try {
  const cliServer = await runCLI({
    command: 'server',
    debug: true, // Enable PHP error logging
  });

  // Your code here

} catch (error) {
  console.error('Server failed to start:', error);
}
```

<Warning>
  Always call `[Symbol.asyncDispose]()` or `server.close()` when you are finished with the server. If the process exits without cleanup, worker threads and temporary directories can persist until the OS reclaims them.
</Warning>
